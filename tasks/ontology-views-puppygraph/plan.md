# 객체 뷰와 PuppyGraph 관계 매핑 구현 계획

작성: 2026-10-05. 상태: 사용자 실행 승인 후 구현·클라우드 검증 중. 단계별 증거와 미완료 사항은 todo.md에 기록한다.

## 목표와 범위

현재 객체·링크·인터페이스 계약을 유지하면서 SQL 뷰와 PuppyGraph 매핑을 구현한다. 객체의 한 행, ID, 속성, 관계의 역할과 출처를 보존하고, 같은 조건에서 원본 SQL과 그래프 조회가 같은 결과를 반환해야 한다. 링크마다 물리 뷰를 만들지 않는다. 설계 카탈로그 → 대시보드 → 대표 경로의 실제 연결 → 전체 확장 → CQ 검증 순서로 진행한다.

기준 목록은 현재 객체 23개, 논리 링크 37개, 인터페이스 3개다. 착수 시 라이브러리와 초안 상태를 다시 확인한다. 물리 뷰 수는 링크별 원본 조사 후 결정하며 미리 목표 숫자를 정하지 않는다. 사용자 요청으로 일봉 OHLC 추가는 보류한다. 기존 데이터에 없는 값을 만들어 채우지 않는다.

## 설계 원칙

- 객체 뷰: 현재 모델의 식별 단위와 ID를 유지한다. 조인으로 객체 행을 증식시키거나 DISTINCT로 오류를 숨기지 않는다.
- 논리 링크: 의미, 양쪽 타입, 방향, 역방향 이름, 개수 관계, 관계 속성을 유지한다.
- 링크의 물리 매핑: 객체 뷰의 FK 재사용 / 기존 연결 원본 재사용 / 정규화가 필요한 공용 연결 뷰 / 원본 부족으로 보류로 구분한다. 기존 원본을 바로 쓸 수 있으면 준비 뷰도 추가하지 않는다.
- 그래프 엣지: 데이터 원본, 양끝 타입·키, 안정적인 식별 규칙, 필터와 속성을 명시한다. 역방향 탐색용 중복 엣지를 만들지 않는다.
- 사건 참여: Actor를 대상으로 하고 참여 기록의 키와 역할을 보존한다. 새로운 참여 업무 객체는 만들지 않는다. Company와 Organization이 공용 연결 원본을 쓸 수 있어도 구체 엣지 매핑은 필요할 수 있다.
- 인터페이스: 논리 계약과 실행 매핑을 구별한다. 우선 구체 타입을 유지하는 결정론적 조회 변환으로 검증한다. 지원 버전에서 공통 라벨 등을 쓸 수 있더라도 중복 노드 생성이나 식별 충돌이 없는지 입증한 뒤 선택한다. LLM이 라우팅하지 않는다.
- SQL과 그래프의 의미 변경을 분리한다. 원본 sourceMapping을 뷰 매핑으로 덮어쓰지 않는다. 그래프 매핑은 검증된 설계와 정의에서 재현 가능하게 생성한다. 범용 SQL 생성기는 이번 범위에 추가하지 않는다.
- DB의 일반 VIEW에 표시하는 PK/FK는 설계상 역할이다. 실제 제약조건처럼 보고하지 않는다.

## 기존 계획과의 충돌

`apps/entity-workbench/docs/puppygraph-pilot-plan.md`의 EventParticipation 객체, Equity 기반 참여 경로, 옛 링크 이름은 현재 모델에 적용하지 않는다. 현재 Actor 기반 정의와 이 계획을 우선한다. 첫 문서 정리 단계에서 기존 문서에 대체 사실을 표시한다. 원본 SQL과의 결과 비교, 외부 데이터 직접 조회라는 시험 취지는 유지한다. 과거 성능 목표는 현재 요구의 합격 기준으로 자동 승계하지 않는다.

루트 `tasks/plan.md`와 `tasks/todo.md`는 다른 분석 기능 계획이므로 보존한다. 기존 과제별 폴더 관례에 따라 이 폴더에 계획과 체크리스트를 저장한다.

각 단계의 세 작업을 순서대로 수행한다. 단계 간에도 앞 단계 검증을 통과한 뒤 진행한다. 실패는 해당 작업에서 수정·재검증하며 업무 의미의 새로운 선택이 필요한 경우에만 사용자에게 보고한다. 각 작업 완료 기록에는 변경 파일, 검증 명령/질의, 결과와 남은 제한을 남긴다.

## 합격 판정과 제한

- 같은 시점의 동일 입력에 대해 객체 ID/값, 엣지 양끝/역할, 필터 결과가 SQL 기준과 일치해야 한다. 건수만 같다고 통과시키지 않는다.
- 데이터가 없는 관계와 구현하지 않은 관계를 별도로 보고한다. 벤치마크 원본 부재와 CalculatedFrom 미구현 같은 항목을 성공으로 세지 않는다.
- 실제 배포 버전의 일반 PostgreSQL 뷰 읽기, 타입별 엣지, 인터페이스 조회 변환은 실행 검증 전까지 미확인이다. 지원되지 않으면 해당 제약을 보고하고 설계에 반영한다.
- 중복 관계를 제거할 때 역할/출처/판본을 잃지 않아야 한다. 복합 ID 인코딩은 기존 값과 바이트 단위로 대조한다.
- 그래프를 쓴다는 이유만으로 성능 향상을 약속하지 않는다. 같은 결과를 기준으로 측정한다.
- CQ 80%는 현재 달성했다고 주장하지 않는다. 목적에 맞는 사용 인정 기준과 데이터 범위를 먼저 고정하고 미지원 질문도 보고한다.
