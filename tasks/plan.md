# 기존 흐름을 유지하는 ETF 중기 분석 추가 계획

## 범위와 결정

기존 티커 분석 및 scan/full 탐색을 유지하고, 여섯 축(동인·차트·수급·매크로·밸류·구성종목)의 중기 분석 경로를 선택적으로 추가한다. 동적 가중치, 자동 주문, 기본 경로 교체는 제외한다. 구현 기본값은 일반 주식형 ETF, 6개월이며 실행 설정에 명시한다. 레버리지·인버스·비주식형은 초기 새 경로에서 지원 제한으로 반환한다.

새 경로는 FMP를 호출하거나 필요로 하지 않는다. 최신 요구인 기존 흐름 보존을 우선하므로 기존 tools/data.py의 FMP 의존성은 이번 프로그램에서 제거하지 않는다. 기존 provider를 공유한다는 이유로 새 경로가 이를 우회 호출해서도 안 된다.

새 코드 위치는 tools/outlook/, 실행 폴더는 _workspace/outlook/<run_id>/로 제안한다. 기존 번호별 산출물·렌더러를 덮어쓰지 않는다. 새 계약은 기존 envelope의 출처·충돌·coverage 개념을 따르되 schema_version과 별도 검사기를 갖는다. 새 환경 의존성은 선택 설치로 격리한다.

아래는 PR 순번이며 실제 GitHub PR 번호가 아니다. 각 PR은 병합 없이 쌓는다. 아래 브랜치 운영 규칙이 이전의 선행 병합 규칙을 대체한다. 전체 교체나 별도 저장소 생성 없이 기능이 동작하는 작은 단위로 추가한다. 최초 계획 작성 브랜치는 feature/factor-model-registry였다.

## 브랜치 운영 — 2026-09-11 사용자 요청

- 출발점: feature/factor-model-registry의 904b527. 기존 팩터 레지스트리를 포함한다.
- 통합 대상: dev/etf-outlook. main, 기존 작업 브랜치, upstream은 변경하지 않는다.
- 준비 PR: chore/outlook-plan → dev/etf-outlook. 기존 계획·명세 보존용이며 PR 01A의 문서 검토를 대신하지 않는다.
- 독립 PR은 dev/etf-outlook을 base로 한다. 선행 변경이 필요한 PR은 선행 PR의 head에서 분기하고 그 브랜치를 base로 하는 stacked PR로 연다. 본문에 의존성과 검증 범위를 명시한다.
- 모든 PR의 병합은 보류한다. 자동 병합·강제 push·브랜치 삭제를 하지 않는다. 추후 사용자 지시에 따라 선행 PR부터 통합하고 후속 PR의 base를 조정한다.
- 사람 검토·실조회 등 품질 게이트가 미완료인 작업은 draft로 남긴다. PR 생성과 구현·검증 완료를 혼동하지 않는다.
- 최종 기준 브랜치로의 통합은 별도 승인 사항이다.

- 의존: 09. 예상 5파일. 순수 분석 비교는 동일 고정 자료를 양쪽에 주고, 운영 비교는 각 공급자의 날짜·커버리지 차이를 공개한다. 신구 점수가 다르다는 이유로 우열을 판정하지 않는다.

## 모든 PR의 병합 조건과 롤백

- 기존 score/validate/check_workspace self-check와 관련 회귀 테스트를 유지한다. 새 코드 테스트는 python -m unittest discover -s tests를 기본으로 한다. 계획 작성 시 테스트를 실행한 것은 아니다.
- 해당 PR의 변화·검증·미지원 항목을 기록한다. 네트워크 검증은 오프라인 테스트와 구분하고, 미실행을 숨기지 않는다. 빌드가 없는 스크립트 저장소에 불필요한 빌드 성공 주장을 추가하지 않는다.
- 새 경로의 기본값 전환·기존 FMP 제거·기존 경로 폐기는 이 계획에 포함하지 않는다. 문제가 생기면 새 경로 호출을 중단하고 기존 경로로 운영한다. 기존 결과를 새 결과로 덮어쓰거나 실패를 구버전 결과로 숨기지 않는다.
- 기본 전환은 별도 PR에서 다룬다. 근거 정확성·중복 내성·결측 처리·고객 이해도와 전향적 전망 평가를 확인한 후 결정한다. 회고 LLM 평가는 사후 학습 지식의 영향을 받을 수 있다.
