# ETF 중기 전망: 실행·분석 명세 v0.1

상태: PR 01A 검토안. 실행 가능한 기능이나 승인된 분석 정책을 뜻하지 않는다.
적용: 일반 주식형 ETF의 명시적 신규 분석 요청. 기존 분석·점수·FMP 경로는 변경하지 않는다.

## 사용자가 받는 답

질문은 하나다: **이 ETF의 중기 전망은 어떠한가?**
기본 기간은 6개월이며 통화·벤치마크·판단 시각과 함께 결과 첫머리에 표시한다.
명시된 `horizon_months`는 양의 정수인 달력 개월 수로 검증하고 모든 분석·평가 단계에 전달한다.
사용자가 다른 기간을 지정하면 임의로 6개월로 되돌리지 않는다. 필요한 자료가 부족하면 해당 기간의 판단을 제한한다.
‘좋은 사업’과 ‘현재 가격에서 좋은 투자’를 구분하고 절대 방향과 상대 성과를 별도로 답한다.
미확보 자료는 중립 점수로 바꾸지 않는다. 여섯 축 투표·합산 점수·동적 가중치는 사용하지 않는다.

보고서 순서는 다음과 같다.

1. 한 문단 전망: 방향, 핵심 가정, 가장 강한 반대 설명, 판단의 한계.
2. 여섯 축 관측표: 동인·차트·수급·매크로·밸류·구성종목. 각 행에 대상·시점·출처·결측을 표시.
3. 중요 논점 최대 3개: 관측 → 연결 가정 → 경쟁 설명 → 구별할 증거.
4. 전망을 바꿀 조건: 무엇을, 언제 확인하며, 어느 판단이 달라지는지.
5. 자료 범위: 조사된 보유 비중, 누락 축, 접근 실패, 가격 조정 여부, 비용·호출량.

초기 결론 필드는 `absolute_outlook=positive|mixed|negative|undetermined`,
`relative_outlook=outperform|inline|underperform|undetermined`로 구분한다.
`mixed`는 상반된 근거가 실제로 있는 상태, `undetermined`는 판단 근거가 부족한 상태다.
`inline` 역시 무자료의 대체값이 아니다. 수익률·목표가·상승 확률은 별도 검증 모델 없이는 생성하지 않는다.

## 역할과 지침 소유권

```text
명시적 요청
  → Runner: 검증·수집 계획·MCP/API 호출·계산
  → Evidence Agent: 확보한 본문에서 원문 주장 추출
  → Runner: 계약·참조 검사 및 자료 묶음 확정
  → Analysis Agent: 연결·경쟁 설명·조건부 전망
  → Runner: 검사·부분 실패 처리·보고서
```

Runner는 코드다. 라우팅·재시도·수치 변환·단계 전환을 LLM에 맡기지 않는다.
두 에이전트는 받은 자료만 해석하고 직접 재검색·주문·도구 추가를 결정하지 않는다.
근거 정책은 [evidence-policy.md](evidence-policy.md), 평가 기준은
[evaluation.md](evaluation.md)가 소유한다. 향후 agent 파일에는 역할별 지시와 예시만 두고
Runner가 이 공통 문서의 고정 버전·해시를 함께 전달한다.

진입 규칙은 최종 연결 PR에서 적용한다. `/etf-outlook <symbol>`만 신규 경로로 보내고,
기존 일반 티커 요청·scan/full은 그대로 둔다. 비교는 명시적 `--compare-legacy` 요청에만 수행한다.
이 명령은 현재 구현되지 않았다. ETF 이름/상장시장이 모호하면 후보를 확정하기 전 수집하지 않는다.

## 최소 단계 계약

아래는 의미 계약이다. 실제 JSON 스키마와 검증 코드는 PR 02부터 단계별로 추가한다.

| 단계 | 필수 입력 → 산출물 | 종료 조건 |
|---|---|---|
| 요청 검증 | symbol·market·as_of·horizon_months·benchmark·currency → request | 기본값 공개, 지원 범위 확인. 레버리지·인버스·비주식형은 초기 unsupported |
| 수집 계획 | request·provider 지원표 → collection_plan | 조회 명령·검색식·대상·시간·호출 한도가 코드로 확정됨 |
| 수집·계산 | 원응답 → observations·documents | 출처·단위·시점·조정 기준과 계산 입력 ID 기록. 실패한 축만 unavailable |
| 근거 추출 | 본문 있는 documents → evidence | 각 주장에 원문 위치·유형·대상·시점. 제목만으로 본문 내용을 추정하지 않음 |
| 통합 | observations·evidence → bundle | 참조·수치·원출처·범위 검사. 의미 중복은 후보로 보존하고 해석 단계에서 판정 |
| 분석 | bundle → assessment | 중요한 연결 및 대안, 지지/반대/미확인 증거, 수정 조건. 새로운 원천 사실 생성 금지 |
| 검증·전달 | assessment → validation·report | 형식 복구 최대 1회. 오류 지속 시 실패 영역 표시, 유효 관측은 전달 |

수집·본문 접근 실패에는 사유와 시각을 남긴다. 한 축의 결측이 전체 관측 출력을 막지는 않는다.
대상/시장 식별 오류, 분석 근거 ID의 중대한 불일치, 결론을 지탱하는 수치 오류는 전망 출력을 보류한다.
처리상태 `complete|partial|failed|unsupported`는 투자 방향과 분리한다.
보류 전망도 유효한 결과다. 다만 모든 자료가 유효해도 가설을 구별할 수 없으면 `undetermined`를 사용한다.

실행 폴더는 `_workspace/outlook/<run_id>/`다. DB 없이 요청·원응답·정규화 결과·LLM 응답·검증 결과를 보존한다.
파일에 `schema_version`과 입력/계산/지침 해시를 기록한다. 재개 시 변경된 입력의 하위 단계만 다시 실행한다.
토큰·키·계좌정보는 산출물에 기록하지 않는다. 기존 번호별 산출물을 덮어쓰지 않는다.

## 여섯 관점: 무엇을 보고 어떤 비약을 막는가

| 축 | 확보 가능한 관측 | 허용되는 해석 예 | 금지되는 해석 예 |
|---|---|---|---|
| 동인 | 뉴스·리포트의 고객 수요, 구매 이유, 계약, 경쟁, 마진, 경영·통제권 사건 | 고객 예산 증가는 수요 가설을 지지하나 수주·마진으로 이어지는 조건은 미확인 | 예산 기사만으로 공급사 매출/주가 상승 확정 |
| 차트 | 가격수익률, 상대 성과, 변동성, 낙폭 | 관측 기간의 강세/약세와 위험 상태 설명. 분할 조정 불명이면 수익률 해석 제한 | 상승 추세 자체를 사업 성공의 증명으로 사용 |
| 수급 | 설정·환매, 투자자별 순매매, 거래량을 서로 다른 지표로 보관 | 기관 순매매가 확보된 시장/종목/기간에 한해 순매수 확인 | 거래량 증가를 기관 유입·ETF 설정액 증가로 대체 |
| 매크로 | FRED 금리·달러·신용 등의 수준/변화, 문서상 업종 노출 | 금리 하락의 할인율 경로와 경기 둔화 경로를 구분 | 금리 하락은 모든 ETF에 긍정이라고 고정 |
| 밸류 | 출처가 제시한 배수·추정치·비교군·기준일 | 동일 정의/시점에서 비교하며 실적 기대와 가격 부담을 함께 검토 | PER 10배라는 숫자만으로 저평가 확정 |
| 구성종목 | 운용사 보유종목·비중·기준일, 해당 종목의 확보된 가격 | 조사된 비중과 상위 집중도를 공개하고 ETF 관련성을 판단 | 상위 일부 자료를 전체로 재정규화하거나 기업 수로 영향 계산 |

구성종목은 독립 ‘가점’이 아니라 다른 관점을 ETF에 연결하는 노출 지도이기도 하다.
고객/사업 분석과 오너리스크는 별도 무제한 조사 트랙이 아니다. 공개 문서의 관련 주장만 사용한다.
단일 관측의 경제적 유불리는 연결 맥락에 따라 해석한다. 회귀계수·팩터 수익률을 추정하지 않은 분석을
‘통계적으로 검증된 다요인 수익률 모델’이라고 부르지 않는다.

## Analysis Agent의 판단 순서

1. ETF 노출, 요청 기간 내 영향 가능성, 결론 민감성으로 최대 3논점을 선정하고 이유를 쓴다.
   논점이 없으면 억지로 채우지 않는다. 보유 비중 미확보는 영향 미확인으로 남긴다.
2. 관측의 연결을 `duplicate|exposure|transmission|conflict`로 구분한다.
   연결마다 근거 ID, 가정, 예상 시차, `supported|tentative|unresolved`를 기록한다.
3. 각 중요 논점에 현재 자료와 양립하는 강한 대안을 적는다. 예: 성장 지속 대 주문 선반영.
   단순한 찬반 문장 대신 무엇을 관측하면 두 설명을 구별할지 밝힌다. 여러 설명은 공존할 수 있다.
4. 증거를 가설별 `supports|contradicts|nondiagnostic|unknown`으로 정리한다.
   근거 개수를 확률로 바꾸거나 미확인을 반증으로 취급하지 않는다.
5. 확인된 사업 변화, 가격 기대, 위험 노출을 연결하여 절대/상대 전망을 각각 설명한다.
   핵심 근거가 없으면 방향을 보류하고 필요한 자료를 특정한다.
6. 수정 조건에 대상 지표/사건, 변화 방향 또는 출처 있는 임계값, 확인 시점, 바뀔 판단을 적는다.
   근거 없는 숫자 기준을 발명하지 않는다. 발표 일정 불명이면 ‘다음 공개 공시 확인 시’처럼 상태를 명시한다.

예: 고객 지출 확대 보도와 주가 상승이 함께 있어도 동일 기대의 반영일 수 있다.
수주·이익 추정치와 현재 가격에 대한 자료가 없다면 수요 개선 가능성은 설명하되
‘현재 가격에서의 추가 상승 여력’은 미해결로 둔다. 이것이 문장을 늘리는 대신 가설을 쓰는 목적이다.
