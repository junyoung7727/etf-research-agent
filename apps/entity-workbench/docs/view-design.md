# 객체 뷰와 링크의 물리 매핑

2026-10-05 설계 v3. `/view-design`, `/api/view-design`에서 조회한다. 설계 목록은 배포 완료 목록이 아니다. 실제 적용 상태는 [작업 계획](../../../tasks/ontology-views-puppygraph/plan.md)과 체크리스트에 기록한다.

## 논리 모델과 물리 원본

객체 23개와 논리 링크 37개를 유지한다. 객체 뷰는 23개이며, 추가 공용 연결 뷰는 3개, 재사용하는 기존 연결 테이블은 1개다. 예전의 관계당 한 뷰 설계를 대체한다.

| 방식 | 링크 수 | 예시 |
|---|---|---|
| 객체 뷰 FK 재사용 | 23 | equity.issuer_id → company.id |
| 객체 ID 해소 후 FK | 7 | DART 코드 → 회사 ID, 시장·종목코드 → 증권 ID, 보고 문맥/직접 출처 → 보고서 수집본 ID |
| 공용 연결 뷰 | 5 | Actor 참여 2개, 문서 근거 2개, 실제 뉴스·증권으로 해소한 언급 1개 |
| 기존 연결 테이블 | 1 | event_thread_link |
| 구현 보류 | 1 | FinancialMetric_CalculatedFrom_FinancialMetric |

공용 연결 뷰는 업무 객체가 아니다. 사건 참여에는 participation_id, actor_id, source_event_id, actor_type, role_code, mentioned_name을 둔다. 참여 ID로 같은 Actor의 같은 사건에 대한 여러 역할을 보존한다. Company/Organization은 원본을 공유하면서 타입 필터와 양끝 노드 타입을 각각 명시한다. SourceDocument도 문서 타입별 매핑을 유지한다.

인터페이스 정의가 SQL 뷰나 그래프 노드를 자동 생성하지 않는다. 실제 타입으로 조회를 변환하는 실행 검증은 별도다. 역방향 이름은 같은 엣지를 반대로 읽는다.

실제 PuppyGraph에서는 양끝 라벨만 지정해도 존재하지 않는 타입의 연결이 반환될 수 있었다. 따라서 security_type 등은 실제 프로필 존재 여부로 해소하고 타입별 엣지 필터로 사용한다. 뉴스 언급도 실제 뉴스와 주식이 존재하는 행만 준비 뷰에서 제공한다.

모든 엣지 원본에는 양끝 키의 IS NOT NULL 조건을 추가한다. 조건이 없을 때 NULL 부모를 가진 개념 65,830개가 관계 수에 포함되는 것을 실제로 확인했다. 값이 있는 표본의 경로 일치뿐 아니라, NULL·빈 관계를 포함한 전체 관계 수를 SQL과 대조한다.

SQL numeric은 그대로 유지한다. PuppyGraph 1.13.0의 Bolt Decimal 반환은 큰 금액의 정밀도를 잃었으므로, 그래프 전송에는 숫자의 정확한 문자열을 쓰는 별도 컬럼과 graphValueEncodings를 명시한다. 모델의 Decimal 의미는 바꾸지 않는다. 소비자는 Decimal로 해석해야 하며 숫자 비교·계산을 문자열 정렬이나 float로 수행하면 안 된다. SQL에서 계산하거나 정확한 Decimal 계산 툴을 사용한다. text[]는 실제 배열로 전송한다.

## 카탈로그와 화면

정본은 `data/view-design.json`의 객체 설계, `physicalSources`, 링크별 `physicalMapping`이다. 객체·관계 YAML의 원본 sourceMapping은 유지한다. 물리 매핑에는 원본 ID, 양끝 컬럼, 엣지 ID 컬럼, 필터, 관계 속성 대응을 둔다. ID 해소용 컬럼은 SQL 참조 컬럼이며 업무 속성을 추가한 것이 아니다.

API의 `objects`와 `relations`는 논리 계약, `physicalTables`와 `references`는 ERD 계약이다. 물리 원본 이름 중복·컬럼 누락·참조 타입 불일치를 거부한다. 원본 해시 변화는 경고하며 그래프 스키마 생성은 이 상태에서 거부한다.

ERD는 컬럼·타입·NULL과 PK/FK 역할을 표시한다. 키 표시는 설계상 역할이며 VIEW에 제약조건을 생성했다는 뜻이 아니다. 복합 PK와 PK/FK 동시 역할을 보존한다. 타입에 따라 하나의 참조 컬럼이 Equity 또는 ETF로 연결되며 두 필수 관계로 해석하지 않는다. 선을 선택하면 원본·키·필터를 확인한다.

고정 컬럼 접점과 직각 선, 전체/직접 연결 범위, 키보드 선택·확대·이동·화면 맞춤을 지원한다. 기본 범위는 ETFHolding이다. 보류 링크는 목록에 유지하되 물리 테이블처럼 그리지 않는다. 모든 선 교차를 없애는 것은 보장하지 않는다.

## 데이터 계약과 미완성 항목

객체 ID의 원본 키·순서·인코딩을 유지한다. 조인 중복을 DISTINCT나 임의 첫 행으로 숨기지 않는다. 코드 매핑은 실제 객체 ID로 해소하고 다중 매칭을 검사한다. 원본 기간·판본을 보존하며 최신/특정 시점은 호출 조건으로 선택한다.

미매핑·의미 보정 속성은 typed NULL이다. 일봉 OHLC는 사용자 지시대로 후속이다. 시가총액 단위, 사업부문 기간/회계 범위/분모, 장중 실제 관측 시각, 산업분류 적용일은 추측하지 않는다. 사건 묶음의 현재 상태는 의미는 확정되었지만 산출 보정이 필요하다. CalculatedFrom은 입력 기간·판본 해소 전 보류한다. 벤치마크 데이터 부재와 관계 미구현을 구분한다.

ETFHolding은 날짜별 보유 구성종목과 비중이다. 같은 날 수정 이력이나 편입·편출 사건은 이번 범위가 아니다.
