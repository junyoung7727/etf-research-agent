# 객체모델의 SQL 뷰 설계

2026-10-05 작성. 대시보드 `/view-design`, 읽기 전용 API `/api/view-design`에서 조회한다. 일반 PostgreSQL VIEW의 설계안이며, 실행 가능한 SQL·DB 반영·PuppyGraph 연결은 이번 작업에 포함하지 않는다.

## 설계 원본

- `data/view-design.json`: 검토한 객체 23개와 관계 37개의 뷰 이름, 한 행의 의미, 관계 식별 규칙, 미결 사항과 정의 해시.
- 기존 객체·관계 YAML: 속성, 식별 키, 원본 매핑과 관계 방향. 대시보드의 기존 로더로 라이브러리와 미반영 초안을 읽는다.
- `data/source-schema.json`: 복합 외래키의 모든 열을 표시하는 데 사용하는 원본 스키마 스냅샷.

정의의 내용이 바뀌면 화면에 재검토 경고를 표시한다. 타입 목록이 달라지면 조회를 실패시켜 새 타입의 설계 누락을 숨기지 않는다. 설계 화면은 현재 정의를 편집하거나 운영 DB를 조회하지 않는다.

## 테이블 관계도

뷰 설계 화면 상단의 ERD는 객체 뷰 23개와 관계 뷰 37개를 모두 컬럼 목록이 있는 테이블로 표시한다. 각 행에 컬럼명·PostgreSQL 타입·NULL 허용 여부를 표시한다. 객체 뷰의 식별 컬럼과 관계 뷰의 `edge_id`는 PK, 관계 뷰의 `source_id`·`target_id`는 FK로 표시한다. 이는 설계상 키 역할이며 PostgreSQL 뷰에 실제 PK/FK 제약조건을 생성했다는 뜻은 아니다.

기존 ELK 엔진을 사용하되 컬럼 수에 따라 테이블 높이를 정하고, FK 행과 참조 PK 행의 위치에 접점을 고정한다. 관계 테이블마다 두 FK 참조선이 있으며 전체 설계에는 74개다. 구현 보류 관계는 테이블 테두리와 참조선을 점선으로 구분한다. 원본의 외래키라는 이유만으로 객체 뷰의 다른 속성에 FK 표시를 자동 부여하지 않는다.

배치는 Coffman–Graham 방식으로 한 레이어의 테이블 수를 제한해 여러 행·열로 분산한다. 전체 및 ETF 보유 구성종목 범위에서 가로/세로 비율이 1.2~3인지 회귀 검증하여 긴 세로 열이나 가로 한 줄로 퇴행하지 않게 한다. 컬럼 위치에 고정한 접점과 직각 경로 검증은 동일하게 유지한다.

관계 뷰는 업무 객체 타입이 아니다. 예를 들어 `organization_participates_in_source_event`와 회사 참여 뷰는 모두 `event_argument`의 같은 참여 기록 구조를 각 출발 객체 타입으로 조회하는 설계안이다. 별도의 ‘조직 이벤트 참여자’ 객체를 정의한 것이 아니며, 논리적 관계마다 물리 뷰를 분리해야 한다는 필수 조건도 아니다. 공유 참여 뷰와 타입별 관계 매핑으로 구성할 수 있다는 점은 SQL 구현 전에 검토해야 한다.

처음에는 ETF 보유 구성종목 주변 테이블을 보여 주며, 주소에 객체 또는 관계가 지정되어 있으면 해당 범위로 연다. 전체 보기와 각 테이블의 직접 연결 보기를 전환할 수 있다. 테이블 더블클릭도 범위를 좁힌다. 테이블과 선 선택은 아래 상세 설계에 연결된다. 드래그 이동, 휠 및 버튼 확대·축소, 화면 맞춤, 자동 배치와 키보드 Enter/Space 선택을 지원한다.

`tests/view-map-smoke.cjs`는 실제 브라우저에서 60개 테이블의 전체 컬럼과 PK/FK 역할, 74개 참조선의 정확한 FK→PK 행 접점, 테이블 중첩 부재, 선의 직각 여부와 테이블 내부 통과 부재, 구현 보류 표시, 직접 연결 범위, 상세 조회 연결, 확대·축소와 모바일 폭을 검증한다. 좌표 비교는 SVG 부동소수점 정밀도를 고려해 0.01 단위의 오차만 허용한다. 모든 선의 교차가 없다는 보장은 아니며, 복잡한 영역은 직접 연결 보기로 확인한다.

## 반환 계약

각 객체 뷰는 현재 모델이 정의한 한 건의 단위를 따른다. 원본 키와 복합 ID의 키 순서·인코딩을 유지한다. SQL 컬럼명은 snake_case이며 모델 속성명도 함께 표시한다. PostgreSQL 타입과 NULL 허용 여부는 구현 시 검증할 제안 계약이다.

관계 뷰에는 `edge_id`, `source_id`, `target_id`와 정의된 역할·근거 속성을 둔다. 역방향 이름은 같은 관계 행을 반대로 조회한다. 사건 참여는 `event_argument_id`를 사용해 같은 주체의 서로 다른 참여 기록과 역할을 보존한다. 정의된 N:1 관계에서 다중 매칭이 발생하면 검증 실패로 처리하며 임의의 첫 행을 고르지 않는다.

뷰는 원본이 보존한 기간과 판본을 유지한다. 원본에 없는 수정 이력을 복원한다는 의미는 아니다. 최신·특정 시점 선택은 호출 조건으로 명시한다. 원본 미매핑과 의미 보정이 필요한 속성은 타입을 지정한 NULL을 반환하는 안으로 표시하고, 실제 0이나 유효한 업무 값과 구별한다. 운영 상태는 업무 객체의 새 속성으로 추가하지 않는다.

## 확인할 사항

| 항목 | 아직 결정하거나 확인해야 할 내용 |
|---|---|
| 시가총액 | 금액 배율·통화, 회사 전체 또는 주식 종류별 범위, 실제 평가일 |
| 사건 묶음의 현재 상태 | 의미는 최신 알려진 단계와 그 상태가 알려진 시각으로 확정되어 있음. 원본 산출 로직의 정정·취소·지연 도착 처리를 보정·검증해야 함 |
| 사업부문 수치 | 기간 시작·종료, 연결·별도, 비중의 분모 |
| 계산 입력 관계 | 각 입력을 정확한 재무지표·기간·판본으로 해소하는 계약. 현재 구현 보류 |
| ETF 벤치마크 | 기존 감사에서 ETF 연결 값과 지수 행이 없어 현재는 조회 결과를 만들 데이터가 없음 |
| 장중 수급 | 보고 슬롯과 별개인 실제 관측 시각 |
| 산업분류 | 수집일과 별개인 실제 적용일 |
| 일봉 | 시가·고가·저가 원본 연결. 사용자 지시에 따라 후속으로 둠 |
| ETF 보유 구성종목 | ETF·구성종목·거래일별 보유 구성종목과 비중으로 범위 확정. 같은 날 수정 전후의 별도 이력은 이번 요건에 포함하지 않음 |
| 복합 ID | PostgreSQL에서 생성할 문자열과 기존 ID의 바이트 단위 동일성 |

미결 항목의 상세 처리안은 대시보드 **확인할 사항** 탭과 각 관련 뷰에 함께 표시한다. 원본 부족, 업무 의미 미확정, 구현 검증을 구분한다.

현재 뷰 설계를 진행하기 위해 사용자 결정을 기다려야 하는 항목은 없다. 시가총액의 단위나 수치의 회계 기준은 원본 조사로 확인할 사실이며 사용자 선호로 정하지 않는다. 원본이 부족하면 부족한 상태를 유지한다. ETFHolding은 날짜별 보유 구성종목이며 편입·편출 사건 이력이 아니다.

## 검증 결과와 다음 구현의 통과 조건

이번 변경 후 대시보드 Python 테스트 53개가 모두 통과했다. 새 설계 테스트 7개는 전체 타입 포함 여부, 뷰 이름 제한, 미확정 금액의 NULL 정책, 재무지표의 판본 식별 키, 사건 참여의 역할 보존, 설계 누락 실패, 정의 변경 경고와 계산 입력 관계 보류를 검사한다.

`tests/view-design-smoke.cjs`는 실제 브라우저에서 목록 수, 원본 조인 표시, NULL 처리안, 참여 역할, 계산 입력 보류, 미결 항목, 객체 화면 연결, 모바일 폭과 페이지 오류 부재를 검증했다. 결과와 화면 캡처는 프로젝트 루트 `output/view-design-20261005/`에 있다.

이는 설계 카탈로그와 화면 검증이다. 실제 SQL의 원본 대비 행 수, NULL·중복 ID, 조인 누락·다중 매칭, 단위·기간·판본과 값 대조 검사는 SQL 구현 이후 수행해야 한다. 그 전에는 뷰 또는 그래프 구현 완료로 간주하지 않는다.
