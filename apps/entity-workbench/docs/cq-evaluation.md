# CQ 평가와 분석 상세

합의한 구조는 코드 검사 → 독립 평가 에이전트 → 코드 집계다. 계산 재현은 제외한다. 여러 수치가 들어 있는 문장의 정합성은 답변과 실제 도구 응답을 대조하는 의미 평가이며 자동 계산 검사라고 표시하지 않는다.

- 계약 v3은 공통 기준 3개(사실 정확성·결론 타당성·조사 완결성)와 CQ별 기준 1개(요구 충족)로 평가한다. 세부 확인 사항과 중대 오류는 판정 규칙으로 유지하며 별도 점수로 집계하지 않는다.
- 분석 실행 1건당 독립 평가 에이전트 세션 1개가 네 기준을 모두 반환한다. 내부의 저장 기록 조회·모델 호출은 여러 번일 수 있다. 코드 검사는 평가자 출력과 분리해 구조·근거 참조·기준시각을 검사한다.
- 기존 semantic_grade는 과거 검토로 보존한다. 새 계약의 평가가 없으면 미평가이며 과거 통과를 승계하지 않는다.
- 평가자는 저장된 답변과 도구 응답·workspace·SDK 실행 기록만 읽는다. 외부 조사나 분석 재실행은 하지 않는다. 모든 기준을 한 번씩 판정하고 근거 ID와 실제 문장, 이유를 남긴다. 통과 이유는 짧게, 실패는 위반 규칙·문제 문장 또는 행동·근거·이유를, 보류는 부족한 자료와 미확인 범위를 기록한다.
- 상단 표에는 네 판정만 표시하고 기술 검사는 별도로 접는다. 실패·보류 상세는 기본으로 펼치고 통과·미평가는 접는다. 표의 판정을 누르면 해당 상세가 열린다. 한 실패를 다른 통과와 평균 내어 상쇄하지 않는다.
- 계약 v2의 평가 기록은 보존하지만 v3의 통과로 변환하지 않는다. 재평가 전까지 새 기준은 미평가로 표시한다.
- 미확인과 실행 중단은 합격하지 않는다. 참조 호출 수와 비용은 검증된 참조 실행이 없으면 미설정으로 표시한다. SDK 비용은 실제 청구액이 아닌 기록된 추정치다.
- 벤치마크와 분석 상세는 같은 run_id로 왕복 연결한다. 이 CQ 실행은 고객 DB의 전망 ID가 없으므로 임의의 다른 분석으로 연결하지 않는다.
- 기존 답변, 도구 응답, 과거 검토는 수정하지 않는다. 새 평가는 별도 파일에 저장하고 답변·도구 기록·계약 변경 시 낡은 평가를 무효화한다.

검증: 중대 실패/미평가를 합격시키지 않음, 실패 근거의 제한적 인용, 오래된 평가 감지, 허위 문장·참조 거절, 같은 실행의 왕복 링크, JSON 근거와 페이지 단위 실행 기록, 모바일 화면을 확인한다.

## 실행

기존 v2 SDK 환경에서 `python apps/entity-workbench/integration/judge_cq.py --run <저장된 실행 폴더> --env-file <DeepSeek 환경파일>`로 독립 평가한다. 실제 API 비용이 발생한다. 평가자의 MCP는 저장 응답 읽기만 제공하며 원 분석·DB·외부 웹을 변경하지 않는다. 웹 GET은 모델을 호출하지 않는다.

평가 계약은 `data/cq-evaluation-contract.json`과 기존 `cq-cases.json`으로 구성된다. 호출 참조값은 검증된 실행이 없어 미설정이다. `evaluation.json`은 현재 적용할 평가, `evaluations/<시각>/`은 입력·프롬프트·원문 출력·조회 이력·오류를 보존한다.

## 평가자 검증 한계

실제 CQ05를 두 번 시험했을 때 DeepSeek Flash 평가자는 기존 검토가 지적한 기간·해석 오류를 놓치고 통과를 제안했다. 중대 오류를 개별 항목으로 분리해도 이 반례를 해결하지 못했다. 따라서 이 평가자는 교정 전이며 자동 통과 제안을 최종 합격으로 집계하지 않는다. 원 평가 출력은 감사 폴더에 보존했다. 기능 통합 성공과 평가 정확도 검증은 별개다.

## 이번 변경 검증

- 계약 v3 변경 후 CQ 관련 테스트 60개 통과, 스킵 없음. 이 중 평가기 테스트 17개는 네 판정의 완전성, 기술 검사 분리, 구 계약 무효화, 실패·보류 집계와 단일 평가 세션을 확인한다. SDK 경계는 테스트 대역이며 실제 모델의 새 기준 판정 정확도를 입증하지 않는다.
- Playwright로 4열 표와 공통/CQ 구분, 기술 검사 분리, 통과 접기·실패/보류 펼치기, 판정 클릭, 13개 CQ 선택, 같은 run_id 왕복·새로고침, JSON 근거·SDK 원문 페이지, 390px 모바일 가로 넘침 없음 및 브라우저 오류 없음을 확인했다.
- 전체 검사는 로컬 SQLite 스냅샷 및 EDGE_ONTOLOGY_ROOT의 승격된 라이브러리가 필요하다. 새 평가기 단위 검사는 임시 자료만 사용한다.
- 실행 중인 5186의 종료·재시작은 자동 승인 검토가 blocked by policy로 거절했다. 같은 종료를 우회하지 않고 기존 프런트엔드를 복원했다. 신규 화면은 별도 5188 서버에서 제공한다.
