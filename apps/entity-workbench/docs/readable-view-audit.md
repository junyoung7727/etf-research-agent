# 실제 객체를 이름으로 읽을 수 있는 뷰

2026-10-05. 목적은 에이전트가 관계를 조회한 뒤 대상의 이름을 알아내기 위해 추가 호출하지 않도록 하는 것이다. 내부 ID와 관계의 방향·개수·시점은 유지한다.

## 조사 결과와 변경 범위

23개 객체 뷰와 3개 공용 연결 뷰, 기존 사건 묶음 연결 테이블을 검토했다. 이 중 20개 객체 뷰에 이름 문맥을 추가하고, 16개 타입에 `displayTitle`을 정의했다. 3개 타입은 이미 의미 있는 이름 속성이 있어 기존 뷰를 유지했다.

| 객체 | 발견한 문제 | 반영한 표시 문맥 |
|---|---|---|
| ETFHolding | ID·비중·날짜만으로는 보유 종목을 알 수 없음 | ETF와 보유 증권 각각의 이름·종목코드·시장, 기준일 |
| DailyBar | 같은 날짜에 여러 종목의 일봉이 존재 | 증권 이름·코드·시장, 거래일, 일봉이라는 구분 |
| DailyInvestorFlow | 수급의 대상 종목이 ID로만 제공됨 | 증권 이름·코드·시장, 거래일 |
| IntradayInvestorFlow | 대상 종목과 보고 슬롯이 제목에서 빠짐 | 증권 이름·코드·시장, 거래일, 원본 슬롯 코드 |
| DailyNAV | NAV의 대상 ETF를 추가 조회해야 함 | ETF 이름·코드·시장, 거래일 |
| MarketCapitalization | 시장가치 기록의 대상이 ID로만 제공됨 | 증권 이름·코드·시장, 스냅샷 날짜. 미확정 금액·단위는 그대로 NULL |
| SecurityIndustryClassification | 분류의 대상 종목이 바로 보이지 않음 | 증권 이름·코드·시장, 분류명, 스냅샷 날짜 |
| SecurityListingSnapshot | 상장 정보의 대상 종목이 바로 보이지 않음 | 증권 이름·코드·시장, 스냅샷 날짜 |
| ExchangeSecurityClassification | 원본 종목명은 있지만 연결 대상과 날짜 문맥이 부족 | 해소된 증권 이름·코드·시장, 원본명 대체 표시, 수집일·분류 체계 |
| FinancialMetric | 회사 코드와 복합 ID를 해석해야 함 | 회사명, 회계연도·기간·기간 종류·연결/별도·지표·산출 종류·수신 시각 |
| FinancialReportSnapshot | 보고서 수집본의 회사와 보고 범위가 바로 보이지 않음 | 회사명, 연도·보고 범위·연결/별도·접수번호·수신 시각 |
| ReportedBusinessSegment | 서로 다른 회사의 같은 부문명이 혼동됨 | 회사명·부문명·보고된 기간, 원문 제목과 연결 개념 이름 |
| SourceEvent | 사건 ID 또는 사건 종류만 보임 | 사건 종류·날짜, 원본 인자별 대상 이름/언급과 역할 코드 |
| EventThread | 묶음 ID만으로 어떤 사건인지 알 수 없음 | 사건 종류·개설 시각, 소속 사건들의 대상/역할 요약 |
| MacroObservation | 지표 코드와 날짜만으로 해석해야 함 | 원본 계약의 5개 지표 이름, 날짜·출처. 미등록 지표는 원래 코드를 유지 |
| Equity | 발행회사는 ID로만 참조됨 | 현재 발행회사 이름 추가. 자체 제목은 기존 증권명 유지 |
| Disclosure | 회사 ID만 있고 실제 253건의 원본 제목이 NULL | 발행회사 이름 추가. 원제목이 없으면 회사·공시 종류·보고일·원문 번호로 표시 제목 구성 |
| Concept | 부모 개념이 ID로만 참조됨 | 부모 개념 이름 추가. 자체 이름 유지 |
| ETF | 연결 지수·테마가 ID로만 참조됨 | 명시적으로 연결된 벤치마크·테마의 이름. 연결이 없으면 NULL |
| NewsArticle | 대표 기사·테마가 ID로만 참조됨 | 대표 기사 제목·테마 이름. 기사 원제목 유지 |
| Company / Organization / MarketIndex | 이미 `name` / `seriesName` 보유 | 뷰 유지. 그래프가 `seriesName`도 표시하도록 수정 |

관계용 `actor_participation`, `document_event_evidence`, `document_security_mention` 및 기존 `event_thread_link`는 객체가 아니다. 별도 표시 제목이나 역방향 연결을 만들지 않았다. 그래프 조회는 원래 양 끝 객체의 속성을 반환하며, 공통 인터페이스 탐색은 `targetType`, `targetId`와 함께 `targetTitle`을 같은 쿼리에서 반환한다.

## 표현 규칙

- 이름·종목코드는 현재 마스터에서 조회한다. 과거 날짜 당시의 명칭이나 코드라는 의미를 부여하지 않는다. 원문에 기록된 이름과 원문 제목은 별도 원본 속성에 보존한다.
- `displayTitle`은 읽기 위한 값이다. 유일성·동일성 판단이나 다음 도구 호출에는 타입과 ID를 사용한다. 같은 제목을 가진 판본도 합치지 않는다.
- 제목·이름이 누락되어도 LEFT JOIN으로 원래 기록을 보존한다. 알려진 코드·원본명·명시적 미확인 문구를 표시할 수 있지만 연결 ID를 만들어 채우지는 않는다.
- 여러 사건 인자는 모두 이름/언급과 역할을 함께 표시한다. 묶음에서는 동일 대상·역할·언급의 반복만 요약에서 제거한다. 원본 사건·인자·관계 기록에는 DISTINCT나 대표 행 선택을 적용하지 않는다.
- 사건 제목은 원본 필드를 조합한 표시다. LLM이 만든 사건 해석, 파급력, 최신 상태를 포함하지 않는다.
- 표시용 속성은 라이브러리의 객체 정의에 등록하고 원본 입력과 SQL 파일을 명시한다. `sourceConstraints: null`은 파생 뷰 컬럼이 원본 테이블의 제약을 직접 상속한다고 주장하지 않기 위함이다.
- 로컬 SQLite의 원본 미리보기에는 라이브 뷰가 없다. 해당 표시 속성은 `viewOnlyProperties`로 구분하고, 실제 값은 PuppyGraph 화면에서 확인한다.

## 데이터에서 확인된 빈 곳

- 거래소 분류 4,403건 중 1,720건은 증권 연결이 해소되지 않아 추가 이름·코드가 NULL이다. 원본명·코드로 표시하며 매핑 문제는 유지한다.
- 사업부문 77건에는 원문 제목과 연결 개념명이 없다. 회사명·부문·보고 기간은 사용할 수 있다.
- 사건 82,083건 중 5,906건은 인자 요약이 없다. 사건 종류·날짜와 `No named arguments`로 표시한다.
- ETF 40개의 벤치마크·테마, 뉴스의 대표 기사·테마, 개념의 부모 연결은 현재 데이터에서 비어 있다. 이름을 추정하지 않는다.

## 적용과 검증

계약은 `data/view-display-contracts.json`, SQL은 `sql/views/`에 있다. `scripts/publish_view_titles.py`는 기존 도메인 정의와의 일치 여부를 확인하고 표시 속성을 라이브러리에 반영한다. 라이브러리는 외부 경로로 관리되므로 Git 커밋과 별개다. `scripts/publish_models.py`로 대시보드 발행본을 갱신한다.

`integration/apply_display_views.py`는 한 트랜잭션에서 지정한 뷰를 교체하고 전후 행 수·ID 유일성·기존 값 표본을 비교한다. 이름 컬럼만 뒤에 추가하므로 기존 컬럼의 순서·타입과 SELECT 권한을 유지한다. 원본 적재 테이블은 수정하지 않는다. 기존 뷰 SQL은 로컬 검증 폴더에 보관한다. 추가 컬럼을 되돌릴 때는 의존성을 확인해야 하며, PostgreSQL의 CREATE OR REPLACE만으로 컬럼을 제거할 수는 없다.

`integration/verify_display_graph.py`는 갱신한 23개 객체/36종 구현 관계의 PuppyGraph 매핑을 배포하고, 변경된 20개 타입의 표시 속성 표본을 SQL과 대조한다. 일봉 8,710,783행 전체에서 이름·코드가 해소되고 전체 행 수도 유지됐다. 일봉의 기존 값 대조는 3개 증권 구간 및 표본이며, 전체 ID 정렬 대신 원본 복합 PK·동일 인코딩·유일 키 조인을 근거로 삼는다. 나머지 변경 뷰는 전체 행 수·고유 ID 수를 대조했다.

검증 산출물: `output/ontology-readable-views-20261005/view-verification.json`, `graph-verification.json`. 이 검증은 이름·키·값 전달에 대한 검증이며 CQ 전체나 80% 사용 커버리지 달성을 의미하지 않는다.
